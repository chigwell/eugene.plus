# Proposal

## Why

Текущее резюме eugene.plus позиционирует Eugene Evstafev как Full-Stack Software Developer и недостаточно показывает техническое лидерство, мобильный опыт и выпущенные AI-продукты для роли hands-on CTO в Neybo. Репозиторий также не содержит конфигурации действующего Cloudflare Worker, что делает публикацию обновлённого резюме невоспроизводимой из Git.

## What Changes

- Обновить англоязычное позиционирование на `CTO / Systems Architect`, сохранив фактические должности в истории работы; Cambridge изменить на подтверждённое пользователем `Senior Software Developer (UIS)`.
- Переписать summary и приоритеты навыков под архитектуру, hands-on разработку, техническое лидерство, мобильные приложения и LLM/MCP; включить Cordova и Swift в summary и Technologies.
- Добавить в T Plus PJSC самостоятельную разработку приложения для iOS и Android с нуля для 50,000 внутренних пользователей компании. Не превращать эту цифру в DAU, скачивания или публичные установки; ссылки не публиковать по решению пользователя из-за региональных ограничений.
- Удалить из Cambridge статистику `5.5k+ pushes / 550+ MRs` и акцент на commit rate; сохранить менторство и награду. Отредактировать остальные достижения по принципу задача → личный вклад → результат без новых неподтверждённых фактов.
- Выделить выпущенные продукты и дать проверяемые продуктовые ссылки. Для LLM7 отразить самостоятельную разработку с постоянным использованием multi-agent development и подтверждённую пользователем нагрузку до 28M+ токенов/минуту как пиковую характеристику. Для L’Étual подчеркнуть ответственность за развитие продукта. Не подменять отсутствие подтверждённого App Store/Google Play release management ссылками на библиотеки.
- Согласовать профиль, HTML/SEO, меню и доступные подписи на английском. Исправить печать: сейчас CSS скрывает T Plus и весь более ранний опыт по позиции в списке.
- Добавить минимальную конфигурацию и документацию ручного деплоя существующего Worker, сохранив его ASSETS-поведение и домены. После реализации проверить сборку и резюме, создать conventional commit, push в `origin/master`, опубликовать и проверить ту же ревизию на Worker.

## Capabilities

### New Capabilities

- `professional-profile`: согласованное англоязычное резюме с подтверждёнными достижениями, доступными ссылками на продукты и полноценным отображением на экране и при печати.
- `worker-publication`: воспроизводимая ручная публикация проверенной Git-ревизии резюме в существующий Cloudflare Worker с проверкой доменов и возможностью отката.

### Modified Capabilities

Нет: `openspec list --specs` не обнаружил существующих спецификаций.

## Impact

- Основные изменения: `src/Schemas/Data.js`, `src/Components/Proyects.jsx`, `src/Pages/Resume.jsx`, `src/Components/SEO.jsx`, `src/Components/Profile.jsx`, `src/Schemas/Menu.js`, `src/App.css`, `index.html`.
- Доставка: новый `wrangler.jsonc` и `src/worker.js`, npm-команды и локальная devDependency Wrangler с lockfile, `.gitignore`, README. Детали активной конфигурации сверяются перед реализацией.
- Цель: `chigwell/eugene.plus`, ветка `master`; Cloudflare account `2b1f8c4c716d2aa53e68800810c5ebb0`, Worker `eugene-plus`, production-домены `eugene.plus` и `www.eugene.plus`.
- Вне scope: редизайн сайта, смена React/Vite, новый AI runtime, новые API/сбор данных, настройка CI/CD, удаление старого GitHub Pages, публикация мобильных приложений, отправка отклика и выдумывание соответствия всем требованиям вакансии. TypeSafe/Jev здесь не требуется: задача меняет редакционное содержание и доставку статического сайта, а не программируемую семантическую логику.
- Этот change сейчас содержит только планирование. Реализация, commit/push и деплой начинаются после отдельного запроса применить план.
