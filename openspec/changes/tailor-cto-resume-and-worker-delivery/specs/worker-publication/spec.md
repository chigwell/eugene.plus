# Spec Delta

## Purpose

Обеспечивает воспроизводимую публикацию проверенного резюме из репозитория в существующий Cloudflare Worker с сохранением доменов и контролем результата.

## ADDED Requirements

### Requirement: Публикация существующего сервиса

Ручной процесс публикации SHALL обновлять Worker `eugene-plus` в аккаунте `2b1f8c4c716d2aa53e68800810c5ebb0` и сохранять доступность `eugene.plus` и `www.eugene.plus`. Сайт SHALL обслуживать собранные ресурсы без новых функций обработки пользовательских данных.

#### Scenario: Успешное обновление
- **WHEN** проверенная сборка публикуется в production
- **THEN** оба домена показывают новое резюме, изображения и стили загружаются, а активная версия принадлежит существующему Worker
- **AND** новый Worker или Pages-проект не создаётся

### Requirement: Воспроизводимая доставка Git-ревизии

Репозиторий SHALL содержать документированный процесс установки, сборки, проверки и ручной публикации. Все предназначенные для поставки изменения MUST быть committed и pushed в `origin/master`; production-сборка SHALL соответствовать зафиксированной ревизии. Локальные credentials и временные файлы MUST NOT попадать в Git или публичные assets.

#### Scenario: Поставка после реализации
- **WHEN** проверки завершились успешно и выполняется поставка
- **THEN** создан conventional commit, удалённая ветка содержит его, а отчёт связывает commit SHA с опубликованной Worker version ID
- **AND** нет незакоммиченных изменений, влияющих на опубликованную сборку

### Requirement: Проверки до и после публикации

Доставка SHALL включать успешную production-сборку, проверку обязательного текста, продуктовых ссылок, мобильного экрана и печати. После публикации MUST быть проверены активная версия и оба публичных домена; успешная команда загрузки сама по себе не считается завершённой проверкой сайта.

#### Scenario: Ошибка до деплоя
- **WHEN** сборка, новые проверки или чтение обязательного содержания не проходят
- **THEN** новая версия не публикуется до исправления; существующие несвязанные предупреждения учитываются отдельно

#### Scenario: Ограничен доступ к публичному сайту
- **WHEN** HTTP-проверка получает 403 или иной ответ, который не позволяет проверить страницу
- **THEN** выполняется доступная браузерная проверка; если результат нельзя подтвердить, отчёт явно отмечает это ограничение и не заявляет полную успешную проверку production

### Requirement: Сохранение прежней инфраструктуры

Изменение SHALL сохранять действующие домены, настройки окружения и логику раздачи assets. Старый GitHub Pages и его `/docs` MUST NOT удаляться или перенастраиваться в рамках этого change. Git-интеграция Cloudflare MUST NOT считаться отключённой на основании отсутствия GitHub workflow или отказа API в доступе.

#### Scenario: Недостаточно прав на Builds
- **WHEN** список Cloudflare Build triggers возвращает 403
- **THEN** состояние Git-интеграции отмечается как неизвестное, права и настройки не расширяются автоматически
- **AND** после push проверяется состояние Worker; конкурирующая публикация рассматривается до ручного деплоя

### Requirement: Контролируемый откат

Перед публикацией SHALL фиксироваться текущая рабочая version ID. При подтверждённой регрессии нового релиза процесс SHALL предусматривать возврат предыдущей версии и повторную проверку доменов; ошибочный релиз MUST NOT представляться успешным.

#### Scenario: Регрессия после релиза
- **WHEN** новая версия сломала раздачу assets или обязательное содержание резюме
- **THEN** восстанавливается зафиксированная рабочая версия, результат проверяется, а пользователю сообщаются причина и статус отката
